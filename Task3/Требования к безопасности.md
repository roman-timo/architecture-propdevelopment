## Требования к безопасности данных

1. Необходимо провести классификацию данных, передаваемых во время интреграции с внешней системой.
   Следующие данные будут передаваться при взаимодействии:
   1) Персональные данные собственников
      Данные: биометрия, номер автомобиля
      Классификация: Персональные данные --152-ФЗ
      Риски: утечка данных может привести к серьезным последствиям, в тч юридическим

2. Необходимо получить согласие Собственников на обработку данных внешним оператором (партнерской компанией)

3. Персональные данные должны хранится на внутренних серверах (crm-tenant-db) в зашифрованном виде.
Управление ключами: ключи шифрования хранятся в защищённых аппаратных модулях (HSM), которые обеспечивают надёжное управление криптографическими операциями и ротацию ключей.

4. Передача персональных данных внешнему провайдеру НЕ предусматривается.
   От провайдера сервиса поступают данные биометрии и номера автомобилей. Идентификация данных происходит на стороне внутренних сервисов (tenant-core-app), далее Провайдеру передается подтверждение/отказ о предоставлении сервиса (вход/въезд)

5. Журналирование и контроль доступа
   Логирование: все операции с персональными данными Собственников фиксируются в журналах. Журналы также шифруются.
Контроль доступа: доступ к данным в системе имеет только ограниченный круг сотрудников. Каждый сотрудник получает доступ на основе принципа наименьших привилегий (Least Privilege), а все действия записываются в журнал аудита.

6. Предоставление пользователям контроля над своими данными
   В личном кабинете пользователя нужно реализовать возможность просматривать, корректировать или удалять свои персональные данные, включая фотографии и предпочтения в одежде. Пользователь может в любое время отозвать согласие на обработку данных, что приведёт к автоматическому удалению его данных из системы.

7. Обеспечение безопасности интеграции
   Безопасность API: Все запросы к API используют https, проверку аутентификации и авторизации.

8. Регулярный аудит.
   Необходимо проводить регулярные аудиты информационной безопасности для соответствия нормативным требованиям, например 152-ФЗ, и своевременного выявления уязвимостей.


## Протоколы аутентификации и авторизации

  Аутентификация будет осуществляться по протоколу OAuth 2.0, который позволяет безопасно получать ограниченный доступ к ресурсам без передачи учётных данных пользователя.
  
  Авторизация и назначение ролей будет определено по ролевой модели RBAC. Для данного сервиса внешнего взаимодействия будет выдана роль "External_API", с правами только на получение информации (GET) -- тем самым будет реализован Принцип наименьших привилегий (Least Privilege Access).
  
  Также, необходимо настроить контекстное управление доступом -- доступ к API сервиса должен быть разрешен только для определенного списка ip-адресов (white list) со строго определенными портами.
